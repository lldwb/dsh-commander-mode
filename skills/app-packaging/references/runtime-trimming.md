# 产物体积压缩与运行时裁剪

安装包 / 免安装包太大（平台附件单文件上限、下载带宽、使用者体感）要压下来时的操作知识。核心纪律：**先量化再裁剪**——体积构成、每项压缩后贡献、算法差异都要实测数字说话，别凭「这个文件看着大」删文件。

## 先量化体积构成，再判断目标可达

1. **摸解压后构成**：`du -sh <解压目录>` 与 `du -sh <解压目录>/* | sort -rh | head -20`——自包含运行时（Electron / Chromium、内嵌 Node 底座）解压后常达数百 MB，**主二进制一个就占 80% 以上**，应用自有内容（源码 asar、资源、字典）往往只有 KB 级。
2. **「压缩包 + 在线下载补齐内容」只在有可分离大件时成立**：先核实有没有「可在线补齐」的对象——自有内容小、运行时的大件（主程序、icu、语言包）拆掉任何一个应用就起不来时，这条线直接否定，别设计了半天。
3. **目标差值摆到可压缩项旁边比量级**：把「差多少才达标」与「各项最多能省多少」放一张表里，差一个数量级（如差 24 MB、可省 0.2 MB）就是到不了，换路线。

## 单文件压测：未压缩大 ≠ 压缩后占得多

决策依据是**压缩后的贡献**，不是解压态大小。逐项单独压测每个大文件：

```bash
7z a -t7z -mx=9 -m0=lzma2 <输出>.7z <单个文件>
```

实测反直觉实例：高度重复的文本（许可证全文等）未压缩 20 MB 级、压缩后只剩 0.2 MB 级——**算法吃掉 99%，删它省不下体积还要担合规风险**；另一类（`resources.pak` 这类已压缩/高熵二进制）几乎压不动——删与不删对最终包几乎无影响。**先测再决定删不删**。

## 压缩算法是第二道杠杆

同一份内容按压缩率排序（实测）：**deflate（zip）< gzip < bzip2 < LZMA / xz**。换归档格式常有 30%+ 收益——zip 的 deflate 对主程序（已压缩的二进制）几乎无能为力，LZMA / xz 能再省一大截：

| 形态 | 相对体积（同内容实测） | 说明 |
|---|---|---|
| zip（deflate） | 基准 | 平台默认 / 通用性最好 |
| tar.xz / xz -9 | 基准的 70% 上下 | 主程序单独 xz -9 常比 deflate 省 30%+ |
| 7z（LZMA2，mx=9） | 基准的 65~70% | 7-Zip / WinRAR / 现代系统原生可解；部分打包器是**一等 target**（加配置即出，不用自己写脚本） |

## electron-builder 裁剪三件套（Electron 项目）

1. **`electronLanguages`**：官方三平台机制，裁语言包只留需要的。**匹配规则坑（实测栽过）**：规则是「相等或前缀+分隔符，且两边转小写」——Windows / Linux 语言目录是 `zh-CN.pak`（连字符），macOS 却是 `zh_CN.lproj`（**下划线**），`zh-CN` 匹配不到 `zh_CN`，**mac 的中文包会被一并删掉**、产物只剩英文，而且第一次 CI 测不出来（构建成功、自检只看「有没有裁」）。三平台都要的中文必须写 `[zh-CN, zh_CN]`；`zh_CN` 在 Windows / Linux 上匹配不到任何文件、无副作用。
2. **`afterPack` 钩子**：打包后删运行时组件（软渲染、WebGPU 编译器这类语义上可弃的），**按目标平台分支**（各平台文件不同名：`.dll` / `.dylib` / `.so` + 各自的 `_icd.json`）。删除对象要先在该平台发行包里确认实存（用下面的 Range 探针查包内清单），删错或删漏以日志为准——构建日志里应有删除清单，自检脚本应核对「该删的确实没了」。
3. **`compression`（根级）**：**各 target 的默认值差别很大，必须显式设**。实测：不设时 AppImage 走 mksquashfs 默认 **gzip**（比同内容的 deb 胖 20+ MB，deb 默认 xz）、dmg 走 UDZO（zlib）；根级设 `maximum` 后 AppImage 走 xz、dmg 自动变 UDBZ（bzip2）；NSIS 载荷本来就是 LZMA / 7z、deb 本来就是 xz，不受影响。

## 换小 ICU 的 node 基底（单文件 / SEA 产物）

单文件产物体积超限的常见主因是官方 node 底座内嵌的 **full-icu 数据（约 28 MB）**——先全仓 grep 证实**零 Intl 使用**（`Intl.`、`toLocaleString` 等 `toLocale*`、`localeCompare`），再从源码编译小 ICU 基底替换：`./configure --with-intl=small-icu && make -j`（CI 上做并缓存基底产物，首次全量约 40~80 分钟）。这是**行为等价前提下的瘦身**：代码不碰 Intl API 时 locale 数据用不上，产物可降 20~35 MB。三件配套：① 与 node-sea.md 的注入链路衔接（自编译基底的注入坑见其「已知坑」）；② 交叉编译自编译基底要钉 `-arch`（见 node-sea.md「平台支持与交叉构建」）；③ 零 Intl 的证据要写进提交说明——它是「行为不变」论证的一部分，不是口头保证。

## 删运行时组件必须有验证护栏，且知道护栏的边界

- **启动冒烟开关**：给应用加 `--smoke-test` 隐藏开关——窗口 / 界面就绪后打印一行结构化结果（窗口尺寸、界面关键元素、真实 IPC 往返）并 `exit 0`；失败或超时 `exit 1`。CI 每个平台构建后跑一次、**fail 就不上传**。判据设计要点：不依赖会随环境变的量（如联网数据行数）、单实例锁拿不到时报失败而非静默退出、输出直写 fd 1（`console.log` 后紧跟 `app.exit()` 会丢输出）。
- **无 GPU 的 CI runner 正好打在软渲染删除的风险链上**：软渲染组件只在「没有可用 GPU」时才被用上——CI runner 正是这种环境，冒烟过 = 删掉后还有回退路径（软件合成 / 各平台原生路径）。
- **边界：冒烟测得出「能启动」，测不出「不掉性能」**：删 GPU 相关组件（如 `d3dcompiler`）后冒烟照样过，但本机对照 `gpu_compositing` / `webgl` 从 `enabled` 掉到 `disabled_software` / `disabled_off`——**runner 本来就没 GPU，`disabled_software` 是常态，删与不删输出一模一样**。涉及硬件能力的组件，必须**在有该硬件的机器上**对照这两项状态才算验过；本地验过再上 CI 的「无 GPU 视角」。
- **验证前先清单实例残留进程**：带单实例锁的应用，前一个实例还活着时新实例「启动即退出」——误判成崩溃会让定位绕一大圈（还叠加过 Windows 控制台 GBK 输出按 UTF-16 解码的误判）。验证脚本先清残留再启动。

## 平台差异：别拿一个平台的结论套全部

- **语言包体量平台间差一个量级**：同样 55 个语言包，Windows / macOS 约 48 MB 而 Linux 只有 8.6 MB——Linux 裁剪收益小是**发行包天生小**，不是配置漏了。
- **同一组件各平台体积不同**：软渲染组件 macOS arm64 15.8 MB、Windows 5.3 MB、macOS x64 与 Linux 4.4 MB（都是未压缩）——收益按平台各算各的。
- **解压态与压缩后是两本账**：决策一律看压缩后贡献（见「单文件压测」）。

## 探针：HTTP Range 只取大 zip 的中央目录

查官方发行包 / 大 zip 里有哪些条目、各多大（决定删什么、省多少），**不下载整包**（几百 MB）：zip 的中央目录在文件末尾，用 Range 只取末尾 64 KB（几 KB 到几十 KB）解析即可——先按「末尾 64 KB」探测 `End of Central Directory` 签名，不够再扩大，再按中央目录条目里的偏移取条目（`node:zlib` 解压，不用第三方库）。

```bash
# 取文件总长
SIZE=$(curl -sI <url> | awk -F': ' 'tolower($1)=="content-length" {print $2}' | tr -d '\r')
# 只取末尾 64 KB
curl -s -r $((SIZE-65536))-$((SIZE-1)) <url> -o tail.bin
```

## 验证清单

1. **真实构建裁决**：手工 7z 量化与打包器真实构建口径可能有出入（参数、额外元数据）——以真实构建的产物体积为准，量化只用来筛方向；
2. 构建日志有删除钩子的执行痕迹，自检脚本核对裁剪生效（语言包只剩预期、产物体积打进日志）；
3. **解压验证**：新形态产物真的能解压、解压后结构与 `unpacked` 目录一致（使用者「解压即用」的关键假设——如系统自带解压器对该格式的支持）；
4. 冒烟本地（有 GPU）+ CI（无 GPU）两边跑；
5. 联动点一并查：自动更新 / 资产匹配逻辑按扩展名收产物时，新形态（7z 等）别漏配、非可执行形态别被挑去「执行」。
