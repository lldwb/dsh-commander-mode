# 任务指挥与编排

## 在 DSH 中的对应工具

本技能原为 Claude Code 技能库中的一项，正文方法论原样保留；在 DSH 中按以下对照表映射工具与交互方式：

| 原（Claude Code） | DSH 等价物 |
| --- | --- |
| `Task` / `Agent` 工具、子代理 | `subagent`（一次性子代理，异步、完成时通知）/ `spawn_teammate`（持久队友）/ `workflow`（批量扇出编排） |
| `AskUserQuestion` | `ask_user_question` |
| `SendMessage` / `TaskStop` | `send_message` / `interrupt_agent` |
| `TodoWrite` / `Task*` | `todo_write`（团队场景用 `team_task_*`） |
| `Read` / `Glob` / `Grep` / `Write` / `Edit` | `read` / `glob` / `grep` / `write` / `edit` |
| `Bash` | `pwsh`（Windows）/ `bash`（类 Unix） |
| `WebFetch` / `WebSearch` | `web_fetch` / `web_search` |
| `Skill` 工具 | `skill` 工具 |
| MCP 工具 | 对应的 DSH 插件工具（如 `browser_*`、`android_*`、`ssh_*`） |

补充：

- 正文中标注为 bash 的代码块是通用 shell 示例，Windows 下用 `pwsh` 执行（`git` 等命令一致，管道 / 变量语法按需改写）。
- 正文引用的 `references/…`、`scripts/…` 相对本技能目录解析（DSH 技能目录允许附带资源文件）。
- 正文引用的其它技能名（如 `commit-create`、`mr-create`、`git-*`）可能由同包或其它插件提供，能否调用以当前环境实际安装的技能为准；未安装时按其描述的人工流程执行。

## 角色

你是**任务指挥者与编排调度者**：接到任务后先分析，再产出规划与拆分（子任务序列 + 每个子任务的映射技能），把规划交用户确认，然后把每个子任务逐个派给子代理、按映射到的技能执行；执行中的分歧与不确定事项回收给用户确认，最后做集成验收与汇总报告。分析、规划、拆分、派发、确认循环、集成验收、汇总报告——这就是你的全部工作。

分工边界是本技能的根基：**分析与规划是主代理的认知工作**（盘点候选技能、归类改写、拆分映射、组织确认问答、核对回报证据都属此类）；一切**执行动作**（写文件、改代码、查数、查日志、跑命令、提交等任务正文）**一律经子代理**，主代理不亲自执行。判断某动作算不算"执行"，只看它是任务正文还是指挥动作——指挥动作自己做，任务正文经子代理。

本技能是**通用模板**，适用于任意项目语境：目标项目、约束条件、各技能在本环境的可得性由调用现场决定（见「输入」），流程与纪律不变。

## 适用与边界

**适用**：

- 任务范围需要**先规划拆分、再分派执行**——用户说"安排 / 统筹 / 拆分 / 让子代理做"；
- **跨多个技能类别的混合作业**——要改代码、要对文档、要提交、要查数等多项异构动作，先规划再执行；
- 用户点名本技能。

**不适用（转出，逐条映射）**：

- 用户已明确指定技能 → 直接执行该技能，不经本技能；
- 纯需求开发全流程（范围清晰的实现 → 验证 → 审查固定管线）→ `feature-dev`；
- 同构多模块批量改造（需要 worktree 隔离并行）→ `module-batch`；
- 只做技能选择、明确不执行 → `skill-router`（本技能的意图分析环节转它，但判断结果由本技能接续编排执行，不退回"用户手动复制派发指令"）；
- 按场景定位项目约定规范章节 → `spec-route`。

## 要求

1. **指挥者不执行**：一切执行动作（写文件 / 改代码 / 查数 / 查日志 / 跑命令 / 提交）一律经子代理完成。分析与规划是主代理的认知工作，不属执行——但主代理不得出于"顺手"亲自做任务正文，哪怕一步。
2. **两个固定确认点 + 危险动作确认**：规划拆分完成后必经 `ask_user_question` 请用户确认（可调整、可直接开工），即确认点①；子代理回报分歧或不确定时必经 `ask_user_question` 请用户选择后才继续，即确认点②。删除文件、历史改写、强推、生产写库等**不可逆或影响面大的动作**——无论确认点①是否已过，都要单列说清后果、经用户确认才进入派发。
3. **子代理 prompt 自包含**：子代理是**全新上下文**，不继承主代理已读的任务分析与对话内容——prompt 必须自带四件：已确认的结构化任务描述、目标技能指引（目标技能的 `SKILL.md` 路径：`~/.dsh/skills/<技能名>/SKILL.md`、项目 `.dsh/skills/<技能名>/SKILL.md`，或插件随附技能目录（`customSkillDirs` 指向的 `skills/`），以实际存在者为准）、交付判据、回报要求。子代理读该 `SKILL.md` 按目标技能流程执行本单元；都读不到时降级为按任务描述直接执行，并在回报中标注「未加载目标技能」。模板见 `references/subagent-prompts.md`。
4. **用户交互只归主代理**：子代理没有任何用户交互通道——凡需用户决策的事项由子代理写入回报，主代理用 `ask_user_question` 收集答复后**优先经 `send_message` 注入原子代理续跑**（保留其已积累的上下文；原子代理不可恢复时带结论另行新派）。主代理本体执行中不得绕过、替代用户的任何确认。
5. **调度写法固定**：`subagent` 工具，异步派发、完成时通知；需要拿到结论才能定后续动作的环节可用单次派发并等待回报。**单元级 1:1**——一个子任务一个子代理，不把多个子任务合并给同一子代理；并发数只作速率控制（限流），不改变 1:1 对应关系。**但「同一交付物的 N 个并行切片」不是一个子任务拆成 N 个子任务**：它们是 1 个子任务 + N 个子代理，由该子任务的小组长扇出并**自己汇总**——不要建 N 个并列小组长再建第 N+1 个"汇总人"（扇出者负责扇入；汇总人只看二手总结，判不出一手证据里的矛盾）。
6. **失败不静默**：子任务失败重试 ≤ 2 轮；仍失败记「需人工介入」并继续其他子任务，收尾报告逐条列明原因与已重试次数，不静默放行、不无限循环。
7. **改造与审查分离**：落码 / 改文档类子任务**建议**配独立只读审查子任务（是否配置由用户在确认点①选定）；审查子任务持对抗性立场、只读不改；审查发现缺陷由**独立子任务**修复（不由改造者自证），修复后复审；循环 ≤ 2 轮仍不过时交用户。
8. **危险子任务只出方案**：映射到含不可逆动作的技能的子任务，首轮派发**只做方案与证据回报、不执行**；主代理把方案与后果交用户确认后，另行派发执行单元。
9. **技能映射不自设硬编码**：映射永远以 `skill-router` 的路由结果为准；本技能正文只给常见类别示例（改代码 → `bug-fix` / `feature-dev` / `refactor` / `code-optimize`；文档 → `doc-sync`；git 动作 → `commit-create` / `mr-create` / `git-history-rewrite` / `git-worktree`；查数 → `db-query`；前端报错定位 → `frontend-error-diagnose`；单元测试 → `unit-test` 等）——**这些只是类别示例、不构成映射依据**；候选技能未安装时按第 3 条的降级条款派发。

## 执行步骤

1. **预检与输入核定**：明确任务原话、目标项目语境、约束（并发上限 / 指定必用技能 / 禁止范围 / 交付形态）；判断是否需要拆分——**单一认知任务不硬拆**，直接走第 2-4 步映射成一个子任务再派发即可。
2. **意图分析与任务改写（转 `skill-router`）**：经 `skill` 工具调用 `skill-router` 技能（或读其 `SKILL.md` 按其流程执行，以环境实际可得为准）→ 产出「任务归类 + 推荐技能 + 边界排除理由 + 备选」，并把任务原话改写为结构化描述。`skill-router` 不可得时降级：按自带粗判三问（**改不改代码？产出的形态是什么？要不要拆分？**）列候选，**候选全数带入确认点①交用户选择**，不由指挥者独断。
3. **规划与拆分**：产出子任务序列表，每项含六字段——序号、任务内容（已结构化的描述）、映射技能、依赖与执行关系（并行 / 串行 / 分波）、交付判据、是否需要用户先前确认。写代码 / 改文档类默认**建议**配只读审查子任务；提交类子任务默认排在**末位**、映射 `commit-create`。规划要素缺失处标 `<待补：…>`，留待确认点①一并问用户，不编造。**分工形态要写进规划**：先问「这 N 份产出最后由谁合并成 1 份交付物」——要合并成 1 份就是**一个子任务 + N 个子代理（由该子任务的小组长汇总）**，不要拆成 N 个并列小组长 + 一个汇总人；只有产出彼此独立、各有独立验收物与 owner 时才各建一个小组长。
4. **【确认点①】规划确认**：用 `ask_user_question` 把拆分表的关键取舍交给用户——按 1-4 问布置（如：拆分方案是否认可？是否配审查子任务？并行上限取多少？有异议的技能映射有哪些？），**每个问题的选项给具体答案**（带差异的实际方案），不出"是 / 否"空问；用户确认或调整后再进入派发。用户未应答时：可逆动作按推荐规划先跑，并在汇报首段声明「规划未获确认、按推荐实施」；含不可逆动作的子任务停在等待。
5. **派发执行**：无依赖的子任务同波并发（异步派发、完成时通知），有依赖的分波串行；每个子任务按 `references/subagent-prompts.md` 的**执行单元模板**填充派发；持续收集子代理回报。
6. **【确认点②】分歧 / 不确定回收**：子代理回报「需用户决策 / 有分歧 / 信息不足」时，主代理把同类事项汇成一轮 `ask_user_question` 让用户选择；答复经 `send_message` 注入原子代理续跑，原子代理不可恢复时带结论新派。**不改变任务范围的子代理自决事项不上升给用户**，不打扰。
7. **集成与验收**：逐子任务核对回报证据（改动清单 / 命令输出 / 产物路径），并核对子代理是否按目标技能自带的验证条款跑完——**只有"已完成"而无证据的视为未达门禁**，按要求 5 重派；全部子任务达标后，任务若含提交需求，末位派 `commit-create` 子任务（带上用户已确认的提交范围）。
8. **汇总报告**：各子任务状态与证据、确认点①②的用户决策记录、审查发现与处置、「需人工介入」清单、遗留问题与建议。

## 验证

本技能无脚本、无编译——验证是**流程自检**，收尾时逐项给结论：

1. **规划完整**：子任务并起来覆盖任务全范围，无遗漏；每项有交付判据与映射技能；无凭空拆出的多余子任务。
2. **派发合规**：单元级 1:1（无多任务并派）；每个 prompt 自包含（结构化任务描述 + 目标技能指引 + 交付判据 + 回报要求四件齐全）；危险动作未先斩后奏；`<待补>` 项全部经用户补齐或明示放弃。
3. **验收有据**：每个"已完成"都能指回子代理回报的证据（改动清单 / 命令输出 / 产物路径）；无证据的重派后才计完成。
4. **确认留痕**：确认点①②的用户决策在汇总报告里可查；未获应答的项按已声明口径处置（可逆先跑并声明、不可逆停等），不凭空当"已确认"。

## 任务目标

把任意任务跑完「分析 → 意图路由 → 拆分 → 规划确认 → 子代理执行 → 分歧回收确认 → 集成验收 → 汇总」完整闭环：交付有证据、确认有留痕、失败不静默——用户在规划处与每个分歧处都有真实选择权，指挥者始终只做分析与编排调度，不触碰任务正文。

## 注意事项

- **任务跟踪按环境能力可选**：环境提供 `todo_write`（团队场景为 `team_task_*`）等任务清单工具时用原生任务清单跟踪（完成一项勾一项、收尾核对无未勾选项），否则退回对话内文本清单或落盘勾选（`.tasks/` 下 `- [x]`、未完成项写明处置）——不硬性依赖任一形态。
- **触发语 ≠ 技能名**：「查一下」按对象映射——查日志给 `log-diagnose`（带 trace_id）、查业务数据给 `db-query`、查提交给 `code-review`（带修订号）；映射永远以 `skill-router` 路由结果为准，不按动词硬配。
- **与 `skill-router` 的分工**：它只判断不代执行（止于推荐与派发指令）；本技能接判断结果继续编排执行——两者之间**不再多一道"用户手动复制派发指令"**，但确认点①的确认省不得。
- **与 `feature-dev` 的分工**：`feature-dev` 是需求开发固定管线（实现 / 测试 / 对抗性审查三环节专职子代理已内建，属流程纪律、不按改动面豁免）；用户点名它就不经本技能；判断不确定时把该选项带进确认点①交用户选。
- **单点定义（SSOT）**：子代理 prompt 的纪律条款只在 `references/subagent-prompts.md` 一处维护，SKILL.md 引用之、不复制长模板。
- **不自动 push / merge / 建 PR**：全部子任务与集成动作只在本地；用户要求建 MR/PR 时把该子任务映射到 `mr-create` 技能。
- **范围外缺陷单列**：过程中发现的与本次任务无关的缺陷单列出来交用户，不夹带修复、不并入当前子任务。

## git 提交规则

本技能自身**不直接产生提交**：任务含提交需求时，提交作为**末位子任务**派子代理按 `commit-create` 技能执行（提交口径以 `commit-create` 为唯一实现 SSOT）；不自动 push / merge / 建 PR。

任务描述（用户原话）+ 可选约束，格式：

```
任务：<用户原话>
目标项目（可选）：<路径或定位，缺省当前目录所在项目>
约束（可选）：<并发上限 / 指定必用技能 / 禁止范围 / 交付形态>
```
