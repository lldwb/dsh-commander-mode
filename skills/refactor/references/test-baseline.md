# 测试基线与「重构不变性」规则

## 为什么必须基线先行

重构的验收标准是**对外行为与改前完全一致**——这只能靠"改造前后跑同一套对照"来证明。没有可复跑的基线，重构就只能靠肉眼比对，回归风险不可控。因此：**基线先于改造**，基线的建立与运行属于重构流程的阶段 1。

## 四类基线（按优先级）

| 基线形态 | 适用 | 说明 |
|---|---|---|
| ① 既有测试 | 项目已有相关测试 | 直接运行作为基线；按下方「覆盖度判定」决定是否补齐 |
| ② 契约级测试（新生成） | 无测试或覆盖不足 | 由子代理按本文件规则生成——**只经对外契约交互**，改造前后同一套应同样通过 |
| ③ 输出快照 | 无测试，但入口有**确定性文本输出**（CLI 命令、`--help`、报告类输出） | 改造前采样命令输出落盘，改造后跑同一命令 diff——**逐字一致即行为未变**；配合 `--help` 逐字对比、GUI 冒烟的逐字段对比扩大覆盖面。两个要点：采样参数组合要覆盖正向与只读 / `--dry-run` 路径（覆盖面取决于采样组合）；**采样与对照产物别放测试收集器递归得到的位置**——`node --test` 之类收集器对 `*.test.js` / `*-test.cjs` 整目录递归收集，对照用的旧测试副本、解包的旧树会把统计撑爆（实测：用例数 142 → 257），放非收集路径或改不命中的扩展名，跑正式统计前先清掉采样目录 |
| ④ 契约快照（降级） | 无测试基建（跑不起测试框架） | 用 `scripts/contract-snapshot.py` 抓取改造前后的契约痕迹比对；**只能防契约面变化（路径/签名/注解被改），不能防行为变化**——降级使用必须在报告中写明此局限 |

## 契约级测试的「重构不变性」

测试的价值来自：**只依赖对外契约，不依赖内部实现**。内部依赖链在重构中必然变化，若测试绑定了内部结构，改造后测试失败不能说明行为变了、改造后测试通过也不能说明行为没变。

### 必须遵守

1. **只经对外契约交互**：HTTP 接口（推荐，覆盖面最广）、公开方法签名、CLI 输入输出、消息/事件契约、页面可观测行为。断言落在"输入 → 输出/副作用"上。
2. **覆盖三档场景**：正向（正常参数 → 期望响应）、异常（缺参/非法值/业务条件不满足 → 错误响应）、边界（空值/特殊值/空集合）。
3. **写操作测试可回滚**：事务回滚或使用可清理的测试数据，不污染既有数据。
4. **测试数据用真实关联值**：存在外键/JOIN 约束时先用查询取真实关联 ID，不硬编码猜测值。
5. **每个改造单元至少有一个对应的契约级测试类/用例集**，作为该单元的回归依据。

### 禁止

1. **禁止断言内部调用**（mock 依赖后 `verify(依赖).方法()` 之类）——绑定实现细节，重构后必然失效。
2. **禁止 mock/替换被测单元的内部依赖**（含 `@MockBean` 等改变容器装配的用法）——测试应走真实装配链路，验证端到端行为。
3. **禁止改写既有通过的用例**：补全只追加未覆盖契约的用例；既有用例失败按下方「失败分类」处理。
4. **禁止修改被测源码来让测试通过**——测试适配现状，而非现状迁就测试。

> 上述禁止项的本质：测试若与实现耦合，就会在重构中被"迫"着改，从而失去对照价值。审查子代理应把违反上述规则视为**严重问题**（基线失真）。

## 护栏的反向实测

新护栏（回归用例、冒烟判据、自动化断言）落地时，**至少做一次反向实测**：把被防护的缺陷手工注入（把正确实现改回错误形态），确认护栏真的变红、失败原因指向根因，然后还原，并核对还原后与改前字节一致（哈希或 diff 双证据）。

只看护栏在正确代码上全绿，证明不了它能拦住它声称要拦的东西。尤其判据是**间接信号**时（如经业务通道的回显间接断言参数形态、只认哨兵串不认具体措辞），反向实测是唯一能证明「判据与根因之间有因果」的证据；反向实测还应验证失败路径的行为（非零退出码、失败原因可读），不只是「没通过」。

## 覆盖度判定（既有测试）

按被测单元的对外契约清单（端点/公开方法）逐项比对已有用例：

- **全覆盖**：跳过生成，直接输出"既有测试已覆盖，跳过"+ 运行命令。
- **部分覆盖**：只补未覆盖契约的用例，不动既有用例。
- **无法判定**：视为未覆盖，全量生成。
- 判定最小标准：契约被某个用例以"对外入口 + 目标路径/方法"命中即算覆盖，不要求正向/异常齐全（补全时才补齐三档）。

## 失败分类与失败集合

基线运行后，逐项失败按两类处理：

| 类别 | 判定 | 处理 |
|---|---|---|
| **本次范围相关** | 失败用例覆盖本次改造单元；或失败根因在改动范围内 | **必须先修复再动代码**（含测试自身缺陷：生成测试的编译错误/断言写错，回头修测试） |
| **既有且无关** | 改造前即失败、与本次范围无关 | 记入**失败集合**（记录用例名 + 现象 + 根因初判），标注不阻断；阶段 3 全量回归对比：**一致或缩小 = 未破坏行为；扩大 = 排查** |

失败集合要写进重构报告，作为"哪些失败是改前就有"的证据，避免与本次引入的回归混淆。

## 生成契约级测试的子代理提示词要点

派发测试生成子代理时，prompt 至少包含：

1. 契约路径（子代理自行加载）+ 被测单元范围与对外契约清单；
2. 项目测试基建说明（测试基类/工具类/测试命令，从项目 `AGENTS.md` 或复用既有测试类获取）；
3. 本文件的「重构不变性」规则全文（必须/禁止），并要求对照自检；
4. 要求输出：测试文件路径 + 用例清单（用例名/契约入口/场景类型）+ 运行命令；
5. 明确改造未开始：测试应能在**当前（改造前）**代码上跑通——跑不通说明测试写错了，修测试而非改源码。
