# 重构契约模板（SSOT）

契约是**本次重构的唯一规则源**：目标形态、范围与单元、不可变更项、命名归属、验证命令，全部只在这一份文件里定义。主代理、改造子代理、审查子代理、修复子代理**加载同一份契约**——子代理是全新上下文，不继承主代理已读内容，prompt 中必须给出本文件路径并要求其自行加载。

## 落盘位置

| 场景 | 位置 |
|------|------|
| 默认（过程产物，不入库） | `<项目根>/.tasks/refactor/<重构名>-contract.md` |
| 项目要求契约作为长期规范留存 | 项目文档目录（提交时纳入，随代码演进同步） |

契约一经用户确认即为判定依据；**任何变更都要回到用户确认**，不得在改造过程中自行放宽。

## 模板骨架

> 按本骨架填写；与项目无关的章节可删，留空章节写"无"。示例均为占位符，按项目实际替换。

```markdown
# <重构名> 重构契约

## 1. 目标形态

- 现状：<当前结构长什么样，问题是什么>
- 目标：<改造后结构长什么样；每层/每类的职责边界>
- 参考实现：<同类已改造完成的样例（文件路径），改造者应对照其风格>

## 2. 范围与单元划分

- 范围：<待改造的对象清单（目录/文件/类/页面）>
- 单元划分：<一个单元 = 一组可独立改造且并发不冲突的文件；通常一个入口类/一个页面/一个模块为一个单元>
- 单元与产物映射：<每个单元改成什么、新产物叫什么名字、放在哪 —— 保证并发单元不写同一文件>
- 公共文件处理：<被多单元依赖的基类/工具/配置，是串行处理还是排除在范围外>
- 引用面（迁移 / 改名类必填）：<调用方与引用面由**扫描命令**取数，写明扫描模式、扫描面（扩展名 / 排除目录）与命中数；同一文件内的**惰性 require / 动态调用**单列检查项——按通读枚举会漏，漏掉即断链>

## 3. 不可变更项（冻结清单）

> 逐项核对用；改造后任何一项变化都必须有契约内的明确声明。

| # | 冻结项 | 说明 | 核对方式 |
|---|--------|------|---------|
| 1 | 对外路径/路由/URL | <入口地址一字不改> | 契约快照 + 审查 |
| 2 | 方法签名 | <方法名、参数列表、泛型> | 契约快照 + 审查 |
| 3 | 返回类型与返回内容 | <类型不变；返回内容的字段/key 逐项一致> | 审查逐字段核对 |
| 4 | 异常行为 | <抛出的异常类型、错误码、触发位置不变> | 审查逐方法核对 |
| 5 | 关键注解 | <权限/事务/校验/序列化注解保持在原位置> | 审查 |
| 6 | 视图名/模板路径/前端资源映射 | <字符串一字不差> | 审查 |
| 7 | 外部协议与数据格式 | <请求/响应结构、字段名、编码、分页约定> | 契约快照 + 测试 |
| 8 | <项目特有项> | <配置键、注册项、字典编码等> | <核对方式> |

## 4. 必须迁移 / 必须保留

> 按重构类型填写两侧边界；判断标准要可用"看到什么代码就归哪边"落地。

| 必须迁移到<新层>的内容 | 判断标准 / 典型代码形态 |
|---|---|
| <业务逻辑1> | <例：默认值填充、跨表查询、数据组装、复杂条件分支、数据转换、私有辅助方法> |
| <业务逻辑2> | <...> |

| 必须保留在<入口层>的内容 | 原因 |
|---|---|
| <路由/入参绑定/参数校验注解> | <属于入口层职责> |
| <渲染/响应包装/视图选择> | <依赖入口层基类或框架能力，新层不可用> |
| <安全注解/防重复提交/会话相关> | <框架在入口层生效> |

## 5. 残留检查与例外口径

> 残留 = 改造后仍指向旧结构的引用。判定口径必须**机械可跑**，否则第 8 节的完成标准无法验收。

- 判定口径：**存在性口径**——引用的目标（路径 / 符号 / 文件）在改造后不再存在即计残留。**不用**"命中数 = 白名单条数"这类计数口径：口径一有歧义（算文件名还是算出现次数、含不含非源码引用），检查就无法机械执行。
- **命令先自验证**：写进契约的每条检查命令（grep / 脚本 / 静态检查）先在**改造前**的代码上跑一遍——确认命中的对象与意图一致：既不命中契约要求原样保留的代码（命令与自己的要求打架），也能抓全目标形态（拆成多行的调用、别名引用、非目标扩展名都算漏抓）。抓不全或误命中就**改命令口径**，不改代码去迁就 grep；改不动的盲区作为已知边界写进契约与报告。
- 检查方式：<自建脚本路径 / 既有静态检查命令；扫描面（扩展名、排除目录）>
- 结果口径：<命中数 / 文件数 / 白名单外意外数>，并给出**可复跑命令**。

| # | 有意保留的旧引用 | 位置与数量（实测） | 依据（机械可判优先） |
|---|-----------------|------------------|-------------------|
| 1 | <如：历史变更记录里的旧路径> | <n 处> | <如：该文件在冻结清单内，改它会伪造历史> |

- **冻结正文的自引用兜底**：<被冻结的文档正文里指向已迁移路径的引用改不掉，列出承接换算的对照表，并写明它覆盖了哪些迁移类别（源码/脚本、文档、配置、测试…）——只覆盖一类，其余类别就没有补救>
- **例外登记纪律**：依据优先选**机械可判**项（"在冻结清单内"即可判），避免语义理由（如"与当时产出的语义相符"）——语义理由一遇用户改判立即失效，登记时就要预期它随时可能被推翻。

## 6. 命名与归属

- 新产物命名：<由原名推导的规则，如"原名去 X 后缀 + Y 后缀">
- 包/目录归属：<新产物放哪个包/目录>
- 复用既有产物：<若新产物已存在（前序改造或迁移遗留），是追加还是覆盖 —— 默认追加，禁止改写既有成员>
- 一对一约束：<一个入口对象对应且仅对应一个新产物（如有）>

## 7. 事务与异常约定（如适用）

- <新层的事务注解与读写标记规则>
- <错误表达方式：抛业务异常 vs 返回错误对象；由谁统一处理>
- <禁止事项：如新层不得返回响应包装类、不得返回无类型 Map>

## 8. 验证命令与完成标准

```bash
# 编译
<编译命令，如 mvn compile -pl <模块> -am>

# 基线/回归测试
<测试命令，如 mvn test -Dmaven.test.skip=false -pl <模块> -am -Dtest=<TestClass> -DfailIfNoTests=false>

# 分层/架构测试（如有）
<命令>

# 契约快照
python <skill 目录>/scripts/contract-snapshot.py capture --root <源码目录> --out <快照文件>
```

完成标准：<编译通过 + 基线/回归测试通过（既有无关失败按失败集合放行）+ 审查无严重与规范问题 + 契约快照差异均为预期内>

## 9. 依赖与资源

- 规则源：<AGENTS.md 章节 / 既有同类实现>
- 环境依赖：<测试所需的数据库/中间件是否可用；不可用时的替代验证方式>
- 已知坑：<项目内与本次重构相关的历史坑（如测试基类配置、并发文件冲突）>

## 10. 子代理公共约定（改造 / 审查 / 修复共用）

> 本节是三类子代理**共同遵守**的约定：一次编写、多处加载——编排方派发时把契约路径给子代理并要求其自行加载（子代理为全新上下文，不继承编排方已读内容），本节即其中的公共部分。逐项按项目实际填写；与前几节重复处以本节为子代理视角的汇总入口，**口径必须与前面各节一致**。

| # | 约定 | 内容（按项目实际填写） |
|---|------|----------------------|
| 1 | 技术栈与验证命令 | <语言/构建工具及版本、编译与静态检查命令、端到端实测方式；命令与第 8 节一致> |
| 2 | 测试基线命令 | <基线/回归测试命令、测试基类与工具类、测试数据来源与回滚方式；「重构不变性」规则见 `<skill 目录>/references/test-baseline.md`> |
| 3 | 命名与归属 | <新产物命名规则、包/目录归属、复用既有产物时"只追加不改写"、一对一约束；与第 6 节一致> |
| 4 | 公共文件：允许 / 禁止改动 | <被多单元依赖的基类/工具/配置/构建脚本**默认禁止改动**（只允许新结构调用）；确需改动的在契约中单列、改为串行处理并经用户确认，改造者不得自行扩大> |
| 5 | 失败分类与容错条款 | <本次范围相关的失败必须先修复再动代码；既有且无关的失败记入**失败集合**（用例名 + 现象 + 根因初判）、标注不阻断，收尾对比"一致或缩小 = 未破坏行为"。基线未通过（未按失败分类放行）前不进入改造。子代理只做代码改动与静态自检，**不自行运行构建/测试**（由编排方统一执行，避免并发冲突）；单单元失败不影响其他单元，重试 ≤ 2 次，仍失败记"需人工介入"；验证循环超限停下交用户介入，**不静默放行**> |
| 6 | 报告格式 | <改造子代理：改动清单 + 迁移映射表 + 自检清单；审查子代理：分级问题表（严重 / 规范 / 建议）+ 逐维度结论；修复子代理：逐条「问题 — 修复 — 自证」；各模板见 `<skill 目录>/references/agent-prompts.md`，编排方汇总报告见 `<skill 目录>/references/report-template.md`> |

**三类子代理的用法**：

- **改造子代理**：按第 1–4 项执行并逐项自检；第 5 项决定哪些失败必须修、哪些不阻断。
- **审查子代理**：以第 1–4 项为判定依据（违反即记问题），**只读不写**；报告按第 6 项输出。
- **修复子代理**：只修清单内的最小改动，不得越过第 3、4 项的边界；结论按第 6 项自证。
```

## 编写纪律

- **只写确定的事实**：目标形态与冻结项都要能从代码/规范中找到依据；不确定的标"待确认"，交用户确认后再落笔。
- **可判定**：每条规则都要能被审查子代理机械核对（"看到 X 判为违规"），避免"代码要优雅"这类无法判定的表述。
- **数字要能机械复现**：契约里出现的每个计数都要配一条可复跑命令、口径唯一（实测踩过：声明"9 处"而按任何口径都数不出 9，验收无法执行，两轮审查都卡在这上面）。
- **规则与实现不重复**：项目已有规范（`AGENTS.md`）时**引用章节号**，不复制正文（单点定义）；契约只补充"本次重构特有"的决策。
- **范围写死**：范围外文件明确"不动"，避免改造过程中范围蔓延。
