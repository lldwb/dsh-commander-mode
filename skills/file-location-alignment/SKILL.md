# 位置对齐：先把「在哪」说清，再用「没有」下结论

这个技能只解决一件事：**用户说的那个位置，和我实际能读的那个位置，是不是同一个。**
它不是取文件工具的使用说明；它是取文件之前/之后必须过的两道判断。

## 什么时候必须用它

满足任一条件就停下来做这一步：

1. 用户给的位置是一个**短语**而不是绝对路径（"那个目录"、"test 里"、"诊断包里"、"桌面"、"手机上"）；
2. 同一个短语有 **≥2 种合理含义**（见下面的候选表）；
3. 你准备说「没找到」「0 个」「不存在」「应该是你没导出/被删了」。

## 第一步：把候选位置列出来（同一句话的多义）

| 用户说 | 可能是 | 常见误判 |
|---|---|---|
| "我的 iPhone > xxx" | **「文件」App 的本地目录**（`On My iPhone/<App>`），或 App 自己的 Documents | 把它当成 App 容器去 `devicectl` 里找 |
| "test 目录" | App 内 `Documents/diagnostics_test_output`、文件 App 的 `test` 文件夹、项目里的 `tests/` | 挑一个自己能读的就开工 |
| "在诊断包里" | 手机上的 ZIP、电脑上已下载的 ZIP、网盘里的 ZIP | 只查一处就断言"包里没有" |
| "在 D 盘那个目录" | 精确路径、同名目录有多份、回收站 | 用 `glob` 搜到第一份就当是它 |
| "在远程机上" | 登录用户家目录、`/tmp`、服务运行用户的家目录 | 忽略 `sudo -u` 后的家目录不同 |
| "在模拟器里" | 模拟器沙箱目录、宿主共享目录 | 在宿主上找模拟器的内部路径 |

## 第二步：写清「我能读什么、读不到什么」

把能力边界**先于结论**讲出来，用户才知道该把文件挪到哪。常见边界的实测结论：

- **iOS `devicectl`**：只能读 App 自己的容器——`appDataContainer` / `appGroupDataContainer` /
  `temporary` / `systemCrashLogs`；**读不到「文件」App 的 `我的 iPhone > xxx`**（那是用户级
  本地存储，不属于任何 App 容器）。App 若没声明 `UIFileSharingEnabled` /
  `LSSupportsOpeningDocumentsInPlace`，它的 Documents 也不会以 App 文件夹形式出现在「文件」里。
- **Android `adb`**：能读 `/sdcard`、`/data/local/tmp`、`run-as <pkg>` 的可调试目录；
  **读不到**未 root 的 `/data/data/<pkg>`（除 run-as 允许的部分）。
- **Windows 本机**：能读当前用户与管理员可见的一切，但 `%APPDATA%`（漫游）与
  `%LOCALAPPDATA%` 是两个不同目录；服务账户的家目录与登录用户不同。
- **远程 SSH**：能读的是**登录用户**可见的路径；`sudo` 之后 `$HOME` 会变，`/root` 与
  `/home/<user>` 不是一回事。
- **旧系统 / 已完成的下载**：能读"现在还在"的文件，读不到"已经被清理逻辑删掉"的文件——
  这种情况要拿**源码证据**（清理代码的文件:行号 + 时间窗口）说，不能只说"可能被删了"。

## 第三步：一次枚举完，再报告

- 能一次枚举多个候选的，就**一条命令/一次调用把全部候选列出来**（例如同时列
  `appDataContainer` 与「文件」App 的目录），别一个一个试到天黑；
- 枚举不到（工具没有这个能力）→ **先问一句**"你说的 X 是指 A 还是 B"，或直接告诉用户
  "A 我能读、B 我读不到，请把文件放到 A"；
- 报告格式固定：**查了哪些位置（逐条）→ 每个位置用什么命令/工具 → 各自看到什么 →
  哪些位置根本读不到（附能力依据）**。

## 「没有」的写法（硬要求）

不允许：

- ❌「0 个 ZIP」「没有找到」「不存在」单独出现；
- ❌「应该是你没导出 / 被系统清理了 / 是不是存错了」（没有直接证据时）；
- ❌ 用"我这边没有"推出"你那边没有"。

必须：

- ✅「我在 **A**（命令）里看到 0 个；**B** 我这里读不到（原因）；请你确认文件在哪个位置，
  或把它移到 A」；
- ✅ 如果确实有清理证据：「`ChickenPlugins.swift:301-311` 在分享面板关闭 600 秒后删目录；
  文件 mtime 与删除窗口对得上」——这是证据，不是猜测。

## 反例（真实事故，2026-11-09）

用户说「我明明是导出了 `LiDAR诊断_*.zip`，在这个目录下」「位置：我的iPhone > test」。
团队此前把"test 目录"理解成 App 容器的 `Documents/diagnostics_test_output`，于是：

1. 在容器里取到 6 个**合成测试包**；
2. 据此报告「现有 82 个包里 0 个含鸡器官」「这批数据没有深度信息」；
3. 用户被迫反复解释"我明明导出了"，并说"你这让我压力很大"。

**正确做法**：听到"我的 iPhone > test"时先说明「`devicectl` 只能读 App 容器，读不到
文件 App 的本地目录」，再给两条可执行路径（把 ZIP 拖进 App 的 Documents /
`diagnostics` 目录，或隔空投送到 Mac 的 inbox），而不是拿容器的 0 个去否定用户。
