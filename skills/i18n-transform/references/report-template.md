# 改造报告模板

本文件是 `i18n-transform` 的参考件：阶段 4 的收尾报告模板。**照此结构输出**，缺节即视为报告不完整。

## 何时读本文件

阶段 4 汇总时（改造已完成、审查与验证均已出结论）。

---

## 一、改造报告（正常收尾）

```
# 国际化改造报告 — <模块/范围>

## 改造概要
- 改造线：<A 后端消息 / B 前端文案 / C 参数校验消息 / 组合>
- 改造日期：<yyyy-MM-dd>
- 改造文件数：<n>（后端 <n> / 前端 <n> / 校验注解文件 <n>）
- 新增 Key 数：<n>
- 审查结论：<✅ 通过 / ⚠️ 有警告 / ❌ 需人工介入>
- 验证结论：<✅ / ⚠️ / ❌>
- 重试次数：<n>
- 最终状态：<✅ 完成 / ⚠️ 有警告项待后续处理 / ❌ 遗留致命问题待人工处理>

## 扫描与单元划分
- 范围：<模块/路径>
- 候选文件：<n> 个（含硬编码文案）
- 单元数：<N>（一个文件 = 一个改造子代理）
- 排除清单：<文件> —— <原因：无硬编码 / 已用 Key / 测试文件>

## 改造文件清单
### 后端消息
- <文件路径> —— <替换处数> 处（<n> 个 Key）
### 前端文案
- <文件路径> —— <替换处数> 处（<n> 个 Key）
### 参数校验消息
- <文件路径> —— <注解处数> 处（<n> 个 Key）
### 资源文件
- <默认语言文件> ｜ <中文文件> ｜ <目标语言文件> —— 各新增 <n> 条

## 新增 Key 完整清单
| Key | 原文 | 译文 | 所属文件 |
|---|---|---|---|
| <key> | <原文> | <译文> | <文件> |

## 审查结果（来自审查子代理）
- 审查文件 <n> 个 / 核对 Key <n> 个 / 🔴 <n> / 🟡 <n>
- 🔴 致命问题处理情况：<# > <问题> <涉及文件> <状态：已修复 / 遗留>
- 🟡 警告问题清单：<# > <问题> <涉及文件> <处理建议>

## 验证结果（来自验证子代理）
- 资源文件 <n> 个 / Key <n> 个 / 🔴 <n> / 🟡 <n>
- Key 集合一致性：<一致 / 差异清单>
- 编码与映射：<结论>

## 自检确认
- [ ] 范围内所有硬编码文案已替换，无残留
- [ ] 全部语言资源文件 Key 集合一致，无缺失
- [ ] 值侧编码合规（非拉丁字符按约定转义、译文直写）
- [ ] 未修改任何业务逻辑、方法签名、SQL、权限注解、校验参数
- [ ] 代码注释与日志文案、测试文件均未被改动
- [ ] 既有 Key 与译文未被删除或修改
- [ ] 已按项目构建命令确认可编译

## 注意事项
1. 【需确认】译文专业性——行业术语的准确译法建议由业务/人工复核（见上方 Key 清单译文列）
2. 【需确认】非标准框架/自定义校验注解的 message 是否正确处理，建议人工抽查
3. 【后续工作】本轮未收敛的全局公共 Key，留待专项统一轮次
4. 【回归点】按目标语言实际走查页面文案与接口提示，确认展示正确
```

## 二、遗留问题报告（需人工介入）

重试达到上限仍存在 🔴 致命问题时，单独输出本报告，并在改造报告中标注最终状态为"遗留致命问题待人工处理"。**不因遗留问题阻塞收尾**，但绝不静默放过。

```
# 国际化改造 — 遗留问题报告（需人工介入）

## 重试统计
- 首次审查致命问题数：<n>
- 第 1 次修复后剩余：<n>
- 第 2 次修复后剩余：<n>

## 仍需人工处理的致命问题
| # | 文件:行 | 问题描述 | 阻塞原因 | 建议处理方式 |
|---|---|---|---|---|
| 1 | <文件:行> | <问题> | <自动修复为何无法完成：如自定义注解结构无法解析、涉及跨文件继承链、资源文件被占用> | <人工操作步骤> |

## 影响面
- 未改造完成的文案数：<n>
- 受影响页面/接口：<范围>
- 是否存在资源文件不一致的风险：<是 / 否 —— 说明>

## 建议后续动作
1. <人工处理项与顺序>
2. <处理完成后如何复跑审查与验证（命令 / 调度方式）>
```

## 三、报告落盘

- 落盘位置按仓库约定：项目级 `<项目根>/.tasks/`，全局默认 `~/.dsh/.tasks/`，可用 `--out-dir` 覆盖；**过程产物不入库**。
- 报告里出现的文件路径以仓库相对路径书写，便于评审与后续检索。
